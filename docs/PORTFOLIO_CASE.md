# PulseDesk — кейс для существующего портфолио

**Название:** PulseDesk.

**Кратко:** Telegram-бот, который следит за сайтами и API и помогает разобраться со сбоем от первого сигнала до восстановления.

**Категории:** Telegram, Backend, Web, DevOps.

**Стек:** JavaScript, Node.js 24, SQLite, Telegram Bot API, HTML/CSS, встроенный Node Test Runner.

**Статус:** локально реализован и проверен; живой Telegram-токен и производственный запуск ещё не подключены.

## Текст страницы

Когда сайт или API перестаёт отвечать, важно вовремя узнать о проблеме и понять, что происходит дальше. PulseDesk проверяет доступность, нужный текст и срок сертификата. Подтверждённый сбой становится инцидентом; бот отправляет уведомление с кнопкой «Беру в работу», хранит историю и сообщает о восстановлении.

Проект показывает путь события: проверка → сохранение → инцидент → очередь → сообщение → подтверждение → восстановление. Сбой сети не стирает очередь, а повторные отрицательные измерения не создают новый инцидент каждый раз.

Новые типы проверок подключаются отдельными модулями. Расписание, хранение и уведомления не копируются для каждой новой функции.

В локальной интерактивной демонстрации можно запустить сбой сайта, исчезновение формы или предупреждение о сертификате. Тестовые сервисы, начальные измерения и отправка Telegram явно обозначены.

## Что показывает работа

- Жизненный цикл инцидента и понятный пользовательский сценарий.
- Telegram-команды, inline callbacks, подписки, polling/webhook и приватный доступ.
- Фоновые задачи, SQLite-outbox, повторные попытки и очередь ошибок.
- Модульная архитектура с общей доменной логикой.
- Сервер и адаптивная панель с реальным состоянием хранилища.
- Тестирование сохранности данных, ошибок доставки и границ доступа.

## Показ за 90 секунд

| Время | Действие | Результат |
| --- | --- | --- |
| 0–15 сек | Обзор | Три проверки, история, явная пометка демо |
| 15–35 сек | «Запустить сбой» | Инцидент и тестовое Telegram-уведомление |
| 35–45 сек | «Беру в работу» | Подтверждение инцидента |
| 45–60 сек | «Восстановить» | Закрытие и сообщение о восстановлении |
| 60–75 сек | `/status`, «Доставка» | Общий обработчик команд, очередь и попытки |
| 75–90 сек | «Модули» | Независимые проверки и способ расширения |

Реальные снимки находятся в `artifacts/screenshots`. Видео ещё не записано. Рабочая Telegram-доставка не заявляется подтверждённой до приёмки с новым токеном.

## Отличие от существующих проектов

Сверка выполнена с текущими `D:\Projects\freelance-portfolio\src\content\projects.ts` и `MY_PROJECTS_CATALOG.md`.

| Проект | Его сценарий | Отличие PulseDesk |
| --- | --- | --- |
| StoreFlow / Excel Business | Учёт, таблицы и перемещения | Внешние сервисы, измерения и инциденты |
| AI_BOT | AI-диалог, идеи, инструменты аккаунта | Правила и фоновые проверки без AI-диалога |
| AI_Agent_Artik | Агент, инструменты, память, Excel | Очереди и эксплуатация сервисов |
| ai-excel-bot / заказ поставщику | Торговые таблицы | Новый процесс без XLSX и закупок |
| Портфолио / Lumora | Каталог, аккаунты, заявки и витрина | Самостоятельная программа с persistence и событиями |
| Прежний Bot_API | Универсальный HTTP-шлюз | Прикладной мониторинг; архив шлюза не используется |

Карточку Bot_API можно заменить на PulseDesk после согласованного обновления каталога. Старый шлюз и его переработку не следует представлять двумя независимыми продуктами без объяснения происхождения.

## Границы описания

Не указывать вымышленных клиентов, экономию времени и SLA. Не выдавать тестовые сообщения за живую Telegram-доставку. Не обещать exactly-once, многопользовательский SaaS и суточный uptime. Не публиковать ключи и базы. Для кейса достаточно снимков и демонстрации; ссылки на приватные исходники не требуются.
