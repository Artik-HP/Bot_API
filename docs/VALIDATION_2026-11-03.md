# Проверка PulseDesk 0.1.0

Дата: 03.11.2026. Среда: Windows, Node.js **24.21.0**, npm **11.19.0**, встроенный SQLite **3.53.4**. Команды выполнялись в `D:\Проекты\API_BOT`.

## Автоматические проверки

`npm run verify`: синтаксис **22 JavaScript/CJS-файлов**, **27 тестов пройдено**, 0 ошибок, 0 пропусков.

Проверенные группы:

- Два сбоя для подтверждения, дедупликация инцидента и уведомления, восстановление, следующий независимый инцидент.
- Атомарная запись измерения/инцидента/outbox с rollback при ошибке.
- Сохранность монитора, инцидента, inbox и уведомления после закрытия и повторного открытия файла SQLite.
- Lease процесса, запрет второго владельца, возврат просроченного lease.
- Retry с Telegram `retry_after`, пять неудачных попыток и dead queue, ручной повтор, возврат просроченной отправки после аварии.
- Отписка, отмена ожидающих сообщений, удаление подписки исключённого из allowlist пользователя.
- Один сетевой запрос при параллельной ручной проверке, пауза и отмена при выключении без ложного инцидента.
- Контроль фразы, срока сертификата, подключение четвёртого тестового модуля без изменения ядра.
- Ограничение истории, числа проверок, конфигурации и разделение demo/live базы.
- Запрет private/loopback/link-local/mapped IPv4/IPv6, non-HTTPS, credentials, query и DNS со смешанными публичными/приватными адресами. Проверка pinned DNS lookup.
- Секрет Telegram отсутствует в пользовательских ошибках адаптера.
- HTTP-путь demo: сбой → уведомление → подтверждение → восстановление → два сообщения очереди.
- Команды через общий router, запрет посторонних пользователей/групп, реестр команд модулей, callback-подтверждение.
- Обязательный ключ live API, отдельный webhook-secret, сохранение update до HTTP 200, дедупликация update_id.
- Same-origin защита demo, Host-проверка, лимит JSON body, запрет раздачи `.env`, исходников и базы.
- CSP на локальных ресурсах и отсутствие busy-loop при пустом polling-ответе.

`npm audit --omit=dev --ignore-scripts`: **found 0 vulnerabilities** для нового package-lock. Runtime-зависимостей сторонних пакетов нет. Это результат проверки цепочки зависимостей, не утверждение об отсутствии ошибок собственного кода.

## Что не подтверждено

- Живое получение/отправка Telegram новым ботом и реальные inline callbacks: нового токена ещё нет.
- Приёмка внешнего HTTPS reverse proxy, production-webhook, VPS/контейнерного запуска и мониторинга процесса.
- Поведение при длительной нагрузке и устойчивость на нескольких машинах.
- Восстановление из резервной копии рабочего окружения; отдельный backup job не реализован.
- Публичное многопользовательское демо. Текущая демонстрация локальная, одна общая тестовая база, без изоляции посетителей.
- Скринкаст для портфолио и публикация кейса на существующем сайте.

Реальный `.env`, ключи и данные прежнего бота не изменялись. Старый API-ключ больше не используется новым runtime, но его прежняя публикация не устраняется удалением из текущего README: при наличии старого развёртывания ключ нужно отозвать/заменить.
